## Can his frame tell a right-click at all? (no script in there)

- **Tried: CSS.** Failed: a right press sets `:active` and `:focus` just like a left one (headless Chrome, real mouse events over the DevTools protocol). Links and checkboxes, the usual script-free tricks, are stripped by Desktop's scrub (`a`, `foreignObject`).
- **Tried: SMIL with an event start.** Works: `<set attributeName="class" to="on" begin="strip.contextmenu" dur="4s"/>` fires on a right-click only, `begin="strip.click"` on a left-click only, in the frame lab's script-less copy (pictures checked). Details and the event table: `research/mods-api.md` § CSS tricks. Proof drawing: `tools/frame-lab-rclick-test.svg`.

## Live look (Fabio): "that looks cool", but Desktop's menu pops up

- A right-click over him opens Desktop's Copy / Select All menu. He asked to stop it, or to use Ctrl+click.
- **Stopping it: not possible.** Read in `app.asar` (build 6.28899.6.0): the main process builds the menu on `context-menu` and always adds Copy for a non-editable page, so it is never empty; only script in the frame could cancel the event.
- **Ctrl+click: not possible.** Neither CSS nor SMIL sees modifier keys; a Ctrl+click is a `click`.
- **Done instead:** the switches start on `auxclick`, which a middle click fires too, with no menu. Lab: middle and right each gave a toy, swapped it, and fired once. Not seen live: whether a middle click over him starts Chromium's autoscroll in the app.
- **Other triggers thought of, not built:** a little toy box on the band to left-click; a double-click (its first click would start a cookie run).
